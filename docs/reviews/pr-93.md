### P1-1: Approval accepts an open blocking finding

Status: fixed in `2dca4fea1c26befed4e94491b303f9fb6190e0af`.

Open at: `b7623f4a33ef78c5b64dccc0716a51b104d198fa`.

File: `WhatYouCarry.Tools/CodexReview/ReviewOutcome.cs:90-103`.

Trigger: An approving review record has an open P0, P1, or P2 finding.

Expected: An approval has no open blocking finding. The command must return a fault for a record that violates this rule.

Actual: The first round returned approval before checking open findings. Commit `2dca4fe` now faults on an open P0 to P2 finding. The regression test covers P0, P1, and P2, and the author reports that all three cases fail on the old code.

Consequence: The command could report approval while a blocking finding remained open.

Correction: The command now checks open blocking findings before it returns approval.

Regression check: `AnApprovalWithAnOpenBlockingFindingIsAFault` passes for P0, P1, and P2. `AnApprovalWithAnAcceptedRiskApproves` also passes.

### P2-1: An unsupported finding severity can pass as nonblocking

Status: open.

Open at: `4e850b9dc73aac612f96ca9d044d64feb204ac3e`.

File: `WhatYouCarry.Tools/CodexReview/ReviewFindings.cs:47-52`.

Trigger: A review record has an open finding headed `P4-1` and an approving verdict.

Expected: Finding severity values are P0 to P3. P3 is the only nonblocking severity. The command must reject any other severity as a malformed record.

Actual: The parser accepts every digit from 0 to 9. `ReviewOutcomeRules` counts only severities at or below P2, so an open P4 finding does not block approval.

Consequence: The command can approve a record with an unsupported open finding and misreport the review result.

Correction: Reject finding severities outside P0 to P3, and keep P3 as the only nonblocking severity.

Regression check: Add an approving record with an open P4 finding. The command must return a fault. Keep the P3 approval case passing.
