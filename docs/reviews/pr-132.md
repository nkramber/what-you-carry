## Findings

### P2-1: Security updates do not use cross-directory grouping

Status: open.

Open at: `33f81fe3f011072f236bbdd7f94246674fa08e48`.

File: `.github/dependabot.yml:16`.

Trigger: Dependabot raises a security update for an action used in both `/` and `/.github/actions/*`.

Expected: D-774 says one action update covers every configured directory in one PR. D-657 enables Dependabot security updates for this repository.

Actual: GitHub documents that `group-by: dependency-name` applies to version updates only. The group has no `applies-to: security-updates` rule, so the new config does not group security updates across these directories. The current config test checks only for the version group text.

Consequence: A security update can leave one use of the action on the old pin while another use changes. `EachActionUseNamesAPinnedCommit` then rejects the split state, delaying the security fix.

Correction: Add explicit security-update grouping that keeps one action update together across the configured directories, and test that behavior. If D-774 only covers scheduled version updates, record that scope and the separate handling for security updates in the decision and test contract.

Regression check: Verify the Dependabot configuration for a same-action update in both directories for version and security updates. The security update must produce one coordinated change, or the decision and test must state and verify the approved separate policy. GitHub documents the `group-by` limitation in the [Dependabot options reference](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference) and the default scope of groups in [Dependabot errors](https://docs.github.com/en/code-security/reference/supply-chain-security/troubleshoot-dependabot/dependabot-errors).
