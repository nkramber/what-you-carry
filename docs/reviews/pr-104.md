## Findings

### P1-1: A malformed closed finding status passes as known

Status: open.

Open at: `4029e36f62e4c072db3f47d7a1fa0327600f8e81`.

File: `WhatYouCarry.Tools/CodexReview/ReviewFindings.cs:120-125`.

Trigger: A review record has `Status: fixed.` or `Status: fixed without evidence.` for a P0 to P2 finding.

Expected: The parser rejects every status outside the forms in `findings.md`. A fixed status names its fixing revision, an accepted risk names a decision, and withdrawn is exact (F-125, T-2, D-514).

Actual: `IsKnownStatus` accepts any string that starts with a known word. `ReviewFinding.IsOpen` then reads `fixed.` as closed, so the review outcome can approve the record without a fixing revision.

Consequence: A malformed review record can pass the required review gate with an unresolved finding.

Correction: Parse each complete status form and reject a closed status without its required revision or decision id.

Regression check: Add review-record cases for `fixed.` and `fixed without evidence.`. `ReviewFindings.Parse` must reject both, and must still accept the documented fixed, accepted-risk, withdrawn, and open forms.

### P1-2: Fence parsing can expose a fake approving section

Status: open.

Open at: `4029e36f62e4c072db3f47d7a1fa0327600f8e81`.

File: `WhatYouCarry.Tools/ReviewGate/ReviewRecord.cs:150-160`.

Trigger: A valid triple-backtick code block contains two lines that start with `~~~`, then a sample `- Head` and `## Verdict` with an approving value.

Expected: The parser skips all text inside a fenced block, including lines that resemble another fence marker. The real Identity and Verdict sections alone determine approval (F-116, D-179, D-269).

Actual: `LinesOutsideFences` toggles its state for any line that starts with three backticks or three tildes. Markdown closes a fence only with the matching marker. The two tilde lines expose the sample sections, and `FindHead` and `FindVerdict` read their first matching values.

Consequence: An example inside a valid fenced block can supply the effective head and `Ready for owner merge`, despite a different real verdict.

Correction: Track the opening fence character and length. Close a block only on a valid matching fence.

Regression check: Add review-gate tests with a triple-backtick fence that contains tilde lines and fake Identity and Verdict sections. The fake sections must not affect the parsed real record.
