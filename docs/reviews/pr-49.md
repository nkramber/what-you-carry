## Findings

### P2-1: A held controller stick overrides the last mouse look device

- Head: `91d1b6f`
- Location: `WhatYouCarry.Game/Input/InputReader.cs:100-105`
- Trigger: Hold a non-zero right stick, then move the mouse before the next tick.
- Expected: D-243 requires the Game layer to set bit 8 from the device that gave the last look input. The mouse event is the last look input, so the frame must not set `ControllerAim`.
- Actual: `AddMouseMotion` sets `controllerLook` to `false`, but `Read` sets it to `true` whenever the stick remains outside the dead zone. A held stick therefore wins over a later mouse event.
- Consequence: Core applies controller aim assist on mouse-look ticks. The recorded intent does not represent the input device that supplied the last look input.
- Evidence: The control flow at lines 89-105 has no event ordering or stick-change state. `ControllerLookSetsTheAimBit` tests only pre-built `RawInput` values and cannot detect this reader state transition.
- Correction: Track the latest look event, and set the controller flag only when a controller look event supplies the latest non-zero look input. Add a reader regression test for a held stick followed by mouse motion.
