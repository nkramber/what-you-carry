### P1-1: Bot tests race with global console capture

Status: open.

Files: `WhatYouCarry.Tests/BotTests.cs:78-79`, `WhatYouCarry.Tests/BitIdentityTests.cs:52-72`.

Trigger: Run `dotnet test WhatYouCarry.slnx --no-build -m:1` on the effective head. The bot tests call `Program.Main`, which writes to the process-global console, while `TheCommandPrintsTheHashAlone` redirects that same console to a test-local `StringWriter`.

Expected: The required test suite passes reliably, and the bit-identity command test captures only the hash that it invokes (T-3, G-9).

Actual: The full local run failed 1 of 517 tests. `BitIdentityTests.TheCommandPrintsTheHashAlone` expected `6ec00e90c1c85cdb` but captured `bot-run: policy greedy-descender, seeds 3...` from `BotTests.RunLogHasRequiredFields`. A focused run of the two test classes passed, which confirms the failure depends on parallel test timing.

Consequence: The PR adds a nondeterministic failure to the repository test gate. A green CI run does not establish that the suite is isolated.

Correction required: Serialize tests that change process-global console state, or remove the global console dependency from command tests and execution. Add a regression check that runs the affected tests under the repository test command and passes repeatedly.
