## Findings

### P2-1: The documents matrix accepts duplicate category lines

Status: open.

File: `WhatYouCarry.Tools/DocGate/DocGateRules.cs:135`.

Trigger: Add a second `docs/design.md` line with a conflicting disposition after the valid line in an otherwise valid description.

Expected: The `## Documents` matrix has one line per category (PR template, D-376). The gate rejects duplicate lines because they make the disposition for a category ambiguous.

Actual: `CheckMatrix` uses `lines.Find`, so it validates only the first matching line and ignores later duplicates. I appended `- \`docs/design.md\`: Not applicable: no design changes affect this pull request.` to a complete fixture. `doc-gate` returned `pass, 0 problem(s)` over the 17 changed paths, although the diff changes `docs/design.md` and the duplicate contradicts the first line.

Consequence: A PR can pass the new required gate with conflicting document dispositions. The owner and reviewer cannot tell which matrix line records the document state.

Correction: Require exactly one matrix line for each required category, and report duplicates. Reject unknown matrix labels if the gate treats the section as an exact list.

Regression check: Add a test with a duplicate category line and require `DocGateRules.Evaluate` to fail with the duplicate category named.
