## Findings

### P2-1: The documents matrix accepts duplicate category lines

Status: fixed in `f0befdd`.

File: `WhatYouCarry.Tools/DocGate/DocGateRules.cs:135` at the original finding.

Trigger: Add a second `docs/design.md` line with a conflicting disposition after the valid line in an otherwise valid description.

Expected: The `## Documents` matrix has exactly one line per category (D-376). The gate rejects duplicate lines because they make the disposition ambiguous.

Actual: At `887f94f`, `CheckMatrix` used `lines.Find` and ignored later matching lines. The direct trigger passed with zero problems. At `f0befdd`, the rule uses `FindAll`, reports the count, and skips disposition checks for an ambiguous category.

Consequence: Before the correction, a PR could pass the new required gate with conflicting document dispositions.

Correction: `f0befdd` requires one line per category. D-376, the design table, and the skill now state that rule.

Regression check: `DuplicateMatrixLineFails` requires failure and the category count. The focused test passes at `b91bd24`. The live PR description passes `doc-gate`; the same description with the conflicting duplicate fails with one problem.

The earlier suggestion to reject every unknown matrix label has no merit. D-376 defines required categories as a floor. A misspelled required label leaves that category missing, which the gate already rejects. The author records this reason in `docs/reviews/pr-77-response.md`.
