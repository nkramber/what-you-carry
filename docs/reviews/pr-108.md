### P2-1: Reject a short PNG header before reading its fields

Status: fixed in `e4d3543c2c7415537f741672ba5209ff07eea239`.

Open at: `4edcd2c488789729eee5c5a3f409cce80a756fba`.

File: `WhatYouCarry.Tools/TextureTrace/ScreenshotPng.cs:76-81`.

Trigger: A malformed screenshot has an `IHDR` chunk shorter than 13 bytes.

Expected: Reject the screenshot with a `ContextException` that names the path and invalid header. T-2 requires context for each error, and PR-90 exit test 4 covers screenshot reader errors.

Actual: The first round showed that the reader used fixed offsets and threw an index exception. The fix now checks that the chunk has exactly 13 data bytes before it reads those offsets.

Consequence: The old reader could terminate `texture-trace` with an unhandled exception. The new reader reports the malformed header through the command's error path.

Correction: `e4d3543` adds the header-length check and a contextual error.

Regression check: `dotnet test WhatYouCarry.Tests/WhatYouCarry.Tests.csproj --filter FullyQualifiedName~ScreenshotReaderRejectsAnotherForm --verbosity minimal` passed 5 tests, including the short-header case.
