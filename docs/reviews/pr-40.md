## Findings

### P1-1. The workflow can use a `night.json` supplied by the pull request when the fetch fails

- Reviewed head: `2253e534dc52b4685fd33bb6a257a9b8100d060f`
- Location: `.github/workflows/night-gate.yml:26-31`
- Trigger: a pull request checkout contains a root `night.json`, and `git fetch --quiet origin night-results` returns nonzero, including when the branch is absent or the fetch has a transient failure.
- Expected: the absent-record case must fail the gate because only the record from `night-results` is valid (D-177, D-273, D-275, and PR-58 exit test 2).
- Actual: the `else` branch only prints a message. It does not remove a checked-out `night.json`. The later command reads that file. A contributor can add a fresh success record whose commit is on `origin/main`, and the gate then passes without a night result from `night-results`.
- Consequence: a required merge gate can be bypassed during the bootstrap case or any fetch failure. The workflow also treats an authentication or network error as an absent branch without preserving the required failure source.
- Correction: read the record into a path outside the pull request checkout, or remove `night.json` before the fetch and create it only after a successful `git show FETCH_HEAD:night.json`. Add a workflow test that places a valid `night.json` in the PR checkout and verifies that an absent or failed fetch still reaches the absent case and exits 1.
