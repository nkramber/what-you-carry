## Findings

### P1-1: The build-failure record drops carried seeds

Status: open.

Open at: `198a0c9d5b6c90d41042dd58b02f597db240263f`.

File: `.github/workflows/night.yml:129-132`.

Trigger: a night on `main` fails before `night-record` writes `night.json`, such as when the build fails and the seed-planning step does not run.

Expected: D-567 requires each later night on `main` to run the failed seeds in the current record until a night passes them. D-569 requires a promotion to prove that it ran each such seed.

Actual: the shell fallback writes only `commit`, `endedAt`, and `status`. It replaces `night-results` without the prior `failedSeeds`. `ReadRecordSeeds` treats an absent `failedSeeds` field as an older record with no failed seeds.

Consequence: the next night can read no carried seeds, pass without rerunning them, and clear the failure. A branch promotion can also see no failed seed to require.

Correction: keep the failed seeds from the existing `night-results` record in a shell-written failure record when the night did not complete its seed sweeps.

Regression check: start with a `night-results` record that has failed seeds, exercise the no-`night.json` fallback, and assert that the new failure record retains those seeds. Then assert that the next seed plan runs them and promotion blocks until it does.
