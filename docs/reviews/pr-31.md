## Findings

### P2-1: Spread offsets can leave the declared cone

Status: fixed in `1b58d3a`.

File: `WhatYouCarry.Core/Projectiles/ProjectileSimulation.cs:81-83`.

Trigger: A definition with a 15-degree half angle draws both yaw and pitch offsets at 15 degrees.

Expected: Every shot stays inside the spread cone whose half angle is `spreadHundredths` (D-266).

Actual: The code samples two independent offsets and applies both. For an axis along negative Z, 15 degrees in each axis gives an angle of about 21.09 degrees from the axis.

Consequence: A projectile can travel outside the content-defined spread cone. The current test allows 22 degrees, so it does not detect this contract failure.

Correction: Sample a direction inside the cone, or constrain the combined angular offset to the definition half angle.

Regression check: Add a deterministic boundary test that asserts the angle from the axis never exceeds the exact half angle. Run `dotnet test WhatYouCarry.slnx --no-build -m:1` and require the test to pass.

Fix evidence: `Fire` now draws one angle from zero to the half angle and one roll around the direction. `SpreadStaysInsideTheCone` checks five axes and the exact half-angle boundary. The old implementation fails the exact cone assertion. The new test passes.

### P2-2: ArcSolver accepts invalid speed and gravity

Status: fixed in `1b58d3a`.

File: `WhatYouCarry.Core/Projectiles/ArcSolver.cs:28-50`.

Trigger: Call `ArcSolver.Solve(0.0f, 10.0f, origin, origin)` or pass a negative gravity value.

Expected: The method accepts a speed above zero and gravity at zero or above, as its parameter contract states. Invalid input must produce a contextual error under T-2.

Actual: The method has no input checks. A zero-speed vertical solve can return `Reachable` with a unit direction, and negative gravity enters the normal calculation.

Consequence: A caller can receive a direction that claims to be reachable when the projectile cannot move. Invalid physics data can also enter the deterministic simulation without a clear failure.

Correction: Validate finite inputs, require speed above zero, and require gravity at zero or above. Raise a contextual `ContextException` for invalid values.

Regression check: Add tests for zero and negative speed, negative gravity, and non-finite values. Run `dotnet test WhatYouCarry.slnx --no-build -m:1` and require the tests to pass.

Fix evidence: `Solve` now rejects non-finite or non-positive speed, negative or non-finite gravity, and non-finite points with contextual errors. `ArcSolverRejectsABadSpeedOrGravity` covers these inputs. The old implementation throws on none of them. The new test passes.
