## Findings

### P2-1: Caller fields can replace the required level or message

Status: fixed in `e42a0a8`.

File: `WhatYouCarry.Core/Logging/JsonlLogger.cs:91-109`.

Trigger: add a field named `level` to valid run fields, then write an error line.

Expected: D-212 requires one level and one message on every line. `LogFields` also rejects equal names because they have no defined reading.

Actual: the logger writes its `level`, then writes the caller field with the same name. The JSON object contains two `level` properties.

Consequence: a reader can get either severity from one line. A caller can also replace the meaning of the required message.

Correction: reserve `level` and `message`, and reject a caller field with either name before the sink receives the line.

Regression check: write a line with each reserved field name. Require a contextual error and no sink output.

Repeat-review result at `e42a0a8`: `LogFields.AddField` rejects both names before a line exists. `AReservedFieldNameIsAnError` covers both names.

### P2-2: A safe assertion changes the caller context and breaks the next assertion

Status: fixed in `e42a0a8`.

File: `WhatYouCarry.Core/Logging/Invariant.cs:51-65`.

Trigger: call two failed safe assertions with the same valid `LogFields` object.

Expected: D-112 says a safe assertion writes its report and continues. The caller context remains usable after that return.

Actual: the first call adds `assertFile`, `assertLine`, and `assertMember` to the caller object. The second call throws because `assertFile` is already present.

Consequence: a safe failure can turn a later safe failure into an unexpected exception. It can also add assertion fields to a later ordinary log line.

Correction: build the report with a separate field set. Do not change the caller field set.

Regression check: use one context for two safe failures. Require two report lines and no exception.

Repeat-review result at `e42a0a8`: the report uses a copy. The original trigger writes two reports, and the caller fields stay unchanged.

### P2-3: The string encoder emits JSON that the standard parser rejects

Status: open.

File: `WhatYouCarry.Core/Logging/JsonlLogger.cs:156-187`.

Trigger: add a string field that contains an unpaired high surrogate, such as `\uD800`, then write and parse the line.

Expected: the PR-4 JSONL contract and exit test 2 require each emitted line to contain one valid JSON object.

Actual: `AppendQuoted` writes the surrogate unchanged. `System.Text.Json.JsonDocument.Parse` rejects the line because it cannot transcode the invalid UTF-16 text.

Consequence: one accepted message, path, or field value can make the log file invalid at that line.

Correction: emit a valid JSON escape for unmatched surrogates, or reject the value with a contextual error before the sink receives it.

Regression check: test unmatched high and low surrogates in names and values. Require valid JSON or a contextual error with no sink output.

Repeat-review result at `e42a0a8`: the implementation escapes an unmatched surrogate, and the original parser trigger passes. The regression check does not pass completely. xUnit gives the high- and low-surrogate rows one test id and skips one row. Keep this finding open until both rows execute.

### P2-4: The logger helper chain exceeds one level

Status: fixed in `e42a0a8`.

File: `WhatYouCarry.Core/Logging/JsonlLogger.cs:91-196`.

Trigger: trace `BuildLine` through `AppendText` to `AppendQuoted`, and trace `AppendQuoted` to `HexDigit`.

Expected: D-110 permits helpers one level deep, and the review must check that depth.

Actual: a top-level operation calls a helper that calls another helper. The Unicode path adds one more nested helper call.

Consequence: the complete JSON write path requires several nested helper contracts. A later change can miss an escape or a name path.

Correction: keep each helper call one level below the operation that owns the JSON line.

Regression check: inspect the corrected call graph and require no helper-to-helper call in the logger.

Repeat-review result at `e42a0a8`: `BuildLine` calls `LevelName` and `AppendQuoted`. Both methods are leaves, and the prior nested helpers are absent.

### P2-5: Caller fields can prevent every assertion report

Status: open.

File: `WhatYouCarry.Core/Logging/Invariant.cs:53-57`.

Trigger: add `assertFile`, `assertLine`, or `assertMember` to valid run fields, then fail an assertion.

Expected: D-112 requires every assertion failure to write a full report. The report must carry the compiler call site under D-215.

Actual: the report copy keeps the caller field. The helper then adds the same name and throws before `logger.Write` runs.

Consequence: one accepted caller field prevents the mandatory report. A safe assertion also becomes an exception.

Correction: reserve the three assertion field names, or build the trusted call-site fields without a duplicate-name failure.

Regression check: test all three names. Require one report with the compiler call site, and require the selected safe action.
