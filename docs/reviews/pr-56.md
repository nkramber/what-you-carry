## Findings

### P2-1: Unreadable input files crash the texture command

Status: fixed in `c83360e`.

File: `WhatYouCarry.Tools/TextureGen/TextureGenCommand.cs:102-105`.

Trigger: Make a rule file unreadable, then run `texture-gen --root <checkout>`.

Expected: The command reports the file path with context and returns exit code 1 for a bad rule or read failure. This is the command contract at line 23 and the zero-silent-failure rule T-2.

Actual: At the prior head, `File.ReadAllBytes(file)` threw `UnauthorizedAccessException` outside the `ContextException` handler. A direct probe returned exit code 134 and printed an unhandled exception instead of the command error.

Consequence: A damaged or inaccessible texture input can terminate the tool without its documented failure result. CI and an owner workflow that depend on the command cannot classify the failure as a normal texture-generation error.

Correction: Read the palette and each rule inside a contextual read boundary. Convert `IOException` and `UnauthorizedAccessException` into a `ContextException` that names the input path, or catch those exceptions in `Run` with the same contextual result. Apply the same rule to the palette read.

Regression check: Add unreadable palette and unreadable rule cases that assert exit code 1, a named path, and no unhandled exception. Run the focused texture tests and the full suite.
