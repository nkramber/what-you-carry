## Findings

### P2-1: The sentence splitter does not end every sentence at a colon

- Commit: `3ea5f23`
- Location: `WhatYouCarry.Tools/SteCheck/SentenceText.cs:120-134`
- Trigger: A prose line contains a colon followed immediately by a non-space character, such as `Options:the value.`
- Expected: Rule 8.4 and the PR-2 scope state that a colon ends a sentence everywhere. The splitter must create a sentence boundary at that colon.
- Actual: `IsSentenceEnd` returns `false` unless the next character is a space, a tab, or the line end. The checker therefore joins both parts and can apply word-count and grammar rules across the required boundary.
- Evidence: The implementation at line 133 adds the whitespace condition. The roadmap result claims that the checker treats a colon as a sentence end everywhere, but no test covers a colon without whitespace.
- Correction: Make the colon boundary follow the project rule. Add a regression test with a colon followed by a non-space character and assert two sentences.

### P2-2: Nested parentheses do not count as one opaque word

- Commit: `3ea5f23`
- Location: `WhatYouCarry.Tools/SteCheck/SentenceText.cs:136-167`
- Trigger: A sentence contains nested parentheses, such as `Read (the (short) name) now.`
- Expected: Rule 8.5 says text in parentheses counts as one word. The complete parenthesized span must remain opaque.
- Actual: `MaskSpans` pairs the first opening parenthesis with the first closing parenthesis. The outer span ends at the inner closing parenthesis, and the remaining text becomes another token. Word counts and grammar checks can then report the wrong result.
- Evidence: `MaskSpans` uses one `IndexOf(close, spanStart + 1)` call and does not track nesting. No test covers nested parentheses.
- Correction: Track nested parentheses while masking, or reject nested spans with a finding that names the input. Add a regression test that checks the word count and grammar opacity.

### P2-3: The command silently accepts trailing arguments

- Commit: `3ea5f23`
- Location: `WhatYouCarry.Tools/SteCheck/SteCheckCommand.cs:11-30`
- Trigger: Run `ste-check --root . trailing-argument` or `ste-check --root . --unknown`.
- Expected: The command accepts only the documented `--root <checkout>` option. An extra argument is a usage error with exit code 2.
- Actual: The loop processes argument pairs and stops when fewer than two arguments remain. The trailing argument is ignored, and the command returns the repository result instead. A local run returned exit code 0 for both examples.
- Evidence: The loop condition is `i + 1 < args.Length`, and no post-loop check verifies that all arguments were consumed. The existing test covers a missing option but not trailing arguments.
- Correction: Reject an unconsumed argument and add regression tests for a trailing positional argument and an extra option.
