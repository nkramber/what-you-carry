## Findings

### P2-1: The content hash has ambiguous file framing

Status: fixed in `7143fd3`.

File: `WhatYouCarry.Core/Content/ContentHash.cs:45-57`.

Trigger: hash one file with path `a` and bytes `bc`, then hash one file with path `ab` and bytes `c`.

Expected: D-163 and D-221 require the hash to identify each relative path and its bytes. Distinct content sets must produce distinct hash input.

Actual: the implementation appends each path and byte sequence without a length, separator, or file marker. Both inputs become the byte sequence `abc` before SHA-256.

Consequence: a content change can keep the same content hash. A later replay can accept a record against a different content set.

Correction: encode each file with an unambiguous boundary, such as a fixed-width path length, the path bytes, a fixed-width content length, and the content bytes. Keep the sort and duplicate-path check.

Regression check: hash the two sets above and require different hashes. Also hash two multi-file sets with a boundary shift and require different hashes.

Repeat-review result at `7143fd3`: `TheHashFramesEachFile` distinguishes the review trigger, a moved boundary, and an empty file. `ContentHashIsStable` still proves source-order independence and rename sensitivity.

### P2-2: An out-of-range or fractional JSON number escapes without content context

Status: fixed in `7143fd3`.

File: `WhatYouCarry.Core/Content/JsonObjectReader.cs:81-83`.

Trigger: read `{"minDepth":1.5}` or a number greater than `Int64.MaxValue`.

Expected: D-92 and T-2 require every content failure to name the file, the field, and the reason. D-220 assigns the reader the JSON value text, and the validator owns the number shape.

Actual: `Utf8JsonReader.GetInt64()` runs before the validator. For a fractional or out-of-range JSON number, it throws `FormatException`. The method catches only `JsonException`, so the caller receives no content context.

Consequence: malformed content can escape the loader as a platform exception without the file or field that caused the failure.

Correction: preserve the number token as text, or catch the conversion exception and wrap it with `ContentError.Make(path, name, ...)`. Let the type validator reject values that do not fit its whole-number contract.

Regression check: read both a fractional number and an out-of-range integer. Require `ContextException` messages and context fields for the file, field, and reason.

Repeat-review result at `7143fd3`: `ANumberThatNoWholeNumberHoldsNamesTheField` covers fractional, positive overflow, negative overflow, and exponent values. `ValueSpan` preserves the token text, and the validator reports the file, field, and reason.

### P2-3: The string lint rule exempts every method named `Get`

Status: fixed in `7143fd3`.

File: `WhatYouCarry.Tools/DetLint/GameStringScan.cs:39-51,144-149`.

Trigger: scan `inventory.Get("You died")` in a Game source file.

Expected: G-8, D-98, and D-222 require every player-visible literal outside the string table. D-222 permits the id argument to `Strings.Get`, not every call whose method name is `Get`.

Actual: the scanner extracts only the final method name and accepts `Get` without checking that the receiver is `Strings`.

Consequence: a Game method can pass inline player text through any `Get` method, and `det-lint` reports no finding. The required lint gate can therefore miss a user-visible string.

Correction: recognize the `Strings.Get` receiver, or use a syntax and semantic rule that distinguishes the project string-table type from unrelated `Get` methods. Keep the separate engine-name exemptions.

Regression check: require one finding for `inventory.Get("You died")` and no finding for `strings.Get("hub.descend")`.

Repeat-review result at `7143fd3`: `OnlyTheStringTableReceiverExemptsAGet` finds unrelated `Get` calls and accepts the tested string-table receiver forms. `TheEngineListHoldsNoGet` confirms that `Get` is no longer a general engine exemption. The correction remains syntactic because the Game project has no source file and no engine compilation path in this PR.
