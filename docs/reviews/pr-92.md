## Findings

### P2-1: Layout and packer bounds can wrap

Status: fixed in `d96ae19`.

File: `WhatYouCarry.Assets/TextureLayout.cs:271-274`; `WhatYouCarry.Tools/TextureGen/AtlasPacker.cs:38-42`.

Trigger: A layout gives a canvas `x = 2147483647`, `width = 1`, or `y = 2147483647`, `height = 1`. The packer also receives a canvas whose width or height is `int.MaxValue`.

Expected: Reject each canvas outside the 512-pixel atlas, and report the layout path and `at` field for a malformed layout (G-7, T-2, D-506).

Actual: The old layout check added the start and size as `int` values. The sum wrapped below zero, so the parser accepted the invalid rectangle. The old packer added the gutter to the size before its bounds check. That sum also wrapped, so it accepted an invalid canvas.

Consequence: A malformed layout could send Game to an invalid atlas place. The generator could return a place outside the atlas instead of reporting that the canvas does not fit.

Correction: The parser compares each size with the room left by its start. The packer rejects a size beyond the atlas room before it adds the gutter.

Regression check: `LayoutRejectsABadFile` now rejects overflowing x and y cases. `PackerRejectsACanvasLargerThanTheAtlas` now rejects overflowing width and height cases. Both new tests failed against the old implementation and pass on `d96ae19`.
