## Findings

### P2-1: Blend accepts a zero part count

Status: fixed in `6afe1dbe440da38c048c611eb09d63805887a085`.

Open at: `e4a097ed2d31700ddbf7199163331e59fb0193e8`.

File: `WhatYouCarry.Tools/TextureGen/LinearLight.cs:74-82`.

Trigger: A caller invokes `LinearLight.Blend(0, 255, 0, 0)`. The weight check accepts zero because the weight equals the part count.

Expected: The blend needs a positive part count. Invalid input must fail with a contextual argument error under T-2.

Actual: At the original head, the method divided by `parts` and threw `DivideByZeroException`.

Consequence: A caller that supplies a zero denominator gets an unrelated arithmetic failure from a new public API.

Correction: Commit `6afe1db` rejects `parts <= 0` with `ArgumentOutOfRangeException` before checking the weight or dividing. The message names the count.

Regression check: `LinearLightFollowsTheTransferFunction` expects a contextual `ArgumentOutOfRangeException` for zero parts, rejects negative parts, and checks both blend endpoints. The focused test passed at `6afe1db`. At the old implementation, the zero-parts call divided by zero before it could return a byte.
