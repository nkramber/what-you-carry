## Findings

### P2-1: The reader accepts a CRC field before later header fields

Status: fixed in `69c946ac434fbbaae71c599e1284b0cb8853f822`.

Open at: `6b327c94282fa248d68035b5287d91555886f076`.

File: `WhatYouCarry.Core/Replay/RunRecord.cs:212-222`.

Trigger: Read a format-version-2 header with `headerCrc` before `seed`, and set its CRC to the CRC-32 of the bytes before `headerCrc`.

Expected: D-637 requires `headerCrc` to end the line, after every protected field.

Actual: At `6b327c9`, `CheckHeaderCrc` checked the bytes before the marker but did not reject later fields. The validator accepts any field order, so a seed after the CRC could change without changing the checked bytes.

Consequence: A changed trailing field could pass the header integrity check and change the run identity.

Correction: `69c946a` requires decimal CRC digits and the closing brace after the marker. It rejects a later field or other trailing byte with context for `headerCrc`.

Regression check: `dotnet test WhatYouCarry.slnx --no-build --filter FullyQualifiedName~ReplayTests.ACrcFieldBeforeAnotherFieldIsAnError` passed 2/2 cases. The test covers changed and unchanged trailing seeds and a byte before the closing brace. The unchanged writer keeps `EachFlippedBitOfTheHeaderIsAnError` applicable. The author response reports both seed cases failed on the prior reader.

### P2-2: The poll marks a night handled when it only dispatches a notice

Status: fixed in `09c8695076de6d48691ac0b862a9642dd4faf25b`.

Open at: `d32da6bc16c97595834a1ce9e64f1c631bb424ba`.

File: `.github/scripts/night-fixer.sh:32-36`, `.github/scripts/night-fixer.sh:103-108`.

Trigger: A setup step fails, `gh workflow run notify.yml` accepts the dispatch, and the `notify` job later fails because the Pushover secrets, network, or API do not permit delivery.

Expected: D-645 requires a Pushover notice when the night fixer stops. D-642 says a failed send fails the `notify` job. The poll must not treat a queued workflow as a delivered notice.

Actual: At `d32da6b`, `notify` returned success when GitHub accepted the workflow dispatch. The setup failure path then appended the run to `handled` without checking the dispatched workflow.

Consequence: If the dispatched job fails, the owner receives no Pushover notice, and later polls skip the failed night as handled.

Correction: `notify-owner.sh` assigns a unique id to each dispatch, finds that run, and waits for its result with `gh run watch --exit-status`. The poll marks the night handled only after the notice run succeeds.

Regression check: `NightFixerTests.AFailedNoticeRunKeepsTheNightOpen` passed in the 20-test focused run at `db8b3c8`. It makes the fake accept a dispatch and fail its run. The night stays out of `handled`. The test failed on the poll at `d32da6b`.

### P2-3: A poll can remove a live lock before its PID is written

Status: fixed in `db8b3c8eddbc58a661a5445312c017ecb2fce840`.

Open at: `d32da6bc16c97595834a1ce9e64f1c631bb424ba`.

File: `.github/scripts/night-fixer.sh:39-50`.

Trigger: Two polls start together. The first creates the lock directory, then pauses before it writes `lock/pid`. The second poll sees no PID, treats the lock as stale, removes it, and creates a new lock.

Expected: D-643 requires one night fixer session at a time, enforced by the lock.

Actual: At `d32da6b`, the missing PID was treated as proof that the first poll ended. Both polls could then pass the lock and start a session for the same night.

Consequence: Two sessions can modify the same night and create competing branches or pull requests.

Correction: The lock now uses a symbolic link whose target is the poll PID. A `lock.reap` directory from one atomic `mkdir` guards the stale-target check, removal, and new lock creation. A second poll leaves the lock alone. A guard older than ten minutes stops the poll with an error.

Regression check: `NightFixerTests.AGuardOfAnotherPollLeavesTheStaleLock`, `AnOldGuardStopsThePoll`, `ALockWithNoProcessIdStaysAndStopsThePoll`, and `AStaleLockGoes` passed in the 20-test focused run at `db8b3c8`. The guard tests failed on `50862e5`.
