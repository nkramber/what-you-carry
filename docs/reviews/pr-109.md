## Findings

### P2-1: The reader accepts a CRC field before later header fields

Status: open.

Open at: `6b327c94282fa248d68035b5287d91555886f076`.

File: `WhatYouCarry.Core/Replay/RunRecord.cs:212-222`.

Trigger: Read a format-version-2 header with `headerCrc` before `seed`, and set its CRC to the CRC-32 of the bytes before `headerCrc`.

Expected: D-637 requires `headerCrc` to end the line, after every protected field.

Actual: `CheckHeaderCrc` finds the marker and checks only the bytes before it. It does not reject a field after the CRC. `ContentValidator.Check` accepts any field order, so the reader returns a seed that the CRC did not cover.

Consequence: A changed trailing field can pass the header integrity check when the CRC field precedes it. The reader then accepts a different run identity.

Correction: Require `headerCrc` to be the final field and reject any bytes between its value and the closing brace.

Regression check: Add a version-2 header with a valid CRC before a changed trailing `seed`; require `RunRecord.ReadHeader` to reject it. Keep `EachFlippedBitOfTheHeaderIsAnError` green.
