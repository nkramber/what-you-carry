## Findings

### P2-1: Exit tests do not verify session termination

Status: open.

File: `WhatYouCarry.Tests/TestExitTests.cs:11-32`.

Trigger: Run the new Escape or Start test with an implementation that returns the expected Boolean from `TestExit.IsPressed` but does not call `Main.Quit`, write `TestExitMessage`, or return exit code 0.

Expected: `EscapeEndsTheSession` and `StartButtonEndsTheSession` must establish that the corresponding input ends a session with exit code 0 and an end line (D-311; Phase 2 roadmap exit tests 2 and 3).

Actual: Both tests assert only the constants and the return value of `TestExit.IsPressed`. They never instantiate or drive `Main`, observe `Main._PhysicsProcess`, inspect the log, or observe the process exit code.

Consequence: A regression in the integration boundary between the input helper and the game loop can pass all new tests while the required test exit does not end a session or emits the wrong result.

Correction: Add an engine-level test or a testable session seam that drives the Escape and Start paths through `Main` and asserts the end line and exit code. Keep the existing negative-input coverage.

Regression check: Run the two exit integration tests on the old commit and on the correction. The old commit must fail because it has no test-exit path, and the correction must pass with the end line and exit code 0.
